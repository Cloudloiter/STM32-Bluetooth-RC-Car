# STM32 蓝牙遥控小车

基于 **STM32F103C8T6** 的双电机蓝牙遥控小车。手机通过蓝牙串口发送 ASCII 指令，
小车执行前进 / 后退 / 左右转 / 停车，并支持 0~9 档调速。

主控用 STM32CubeMX + HAL 库，通信协议是自己定义的极简单字节指令集，
没有用任何现成的遥控方案或第三方库。

---

## 硬件

| 器件 | 型号 | 作用 |
|---|---|---|
| 主控 | STM32F103C8T6 最小系统板（蓝板） | 主程序运行 |
| 电机驱动 | L298N 双 H 桥模块 | 驱动两个直流减速电机 |
| 电机 | TT 减速电机 ×2 | 左右轮 |
| 蓝牙 | HC-05（固件 2.0-20100601） | 与手机通信，经典蓝牙 SPP 透传 |
| 电源 | 4 节 5 号电池盒（约 6V） | L298N 的 VM 输入 |
| 车体 | 亚克力双层底盘 + 万向轮 | 万向轮用铜柱垫高 |

---

## 接线

### L298N ↔ STM32

| L298N | STM32 | 说明 |
|---|---|---|
| ENA | **PA6** | TIM3_CH1，PWM 控制左轮速度 |
| IN1 / IN2 | **PB0 / PB1** | 左轮方向 |
| IN3 / IN4 | **PB10 / PB11** | 右轮方向 |
| ENB | **PA7** | TIM3_CH2，PWM 控制右轮速度 |
| GND | **GND** | ⚠️ 必须共地，否则信号参考点不同，电机乱转 |

> ENA/ENB 上的跳线帽必须**拔掉**，否则使能端被固定为高电平，PWM 调速不起作用。

### HC-05 ↔ STM32

| HC-05 | STM32 | 说明 |
|---|---|---|
| TXD | **PA10** | USART1_RX，模块发→单片机收 |
| RXD | **PA9** | USART1_TX，单片机发→模块收 |
| GND | **GND** | |
| VCC | 5V | ⚠️ 建议与控制部分共用一路干净电源 |
| STATE / EN | 不接 | EN 拉高会在下次上电进入 AT 模式 |

USART1 参数：**9600-8-N-1**（与 HC-05 固件默认值一致）。

## 指令协议

| 指令 | 动作 |
|---|---|
| `F` | 前进 |
| `B` | 后退 |
| `L` | 原地左转（左轮倒退 + 右轮前进） |
| `R` | 原地右转（左轮前进 + 右轮倒退） |
| `S` | 停车 |
| `1`~`9` | 设置速度档位（每档 PWM 占空比约 11%），不改变方向 |

**指令保持机制**：收到方向指令后，小车持续按该方向行驶，直到收到新的方向指令，
或超过 `CAR_TIMEOUT_MS`（默认 10 秒）没有收到任何合法指令时自动停车。
这个超时同时兼作**断连保护** —— 手机蓝牙掉线时车不会一直跑出去。

**非法字节过滤**：只有 `F/B/L/R/S/0~9` 会进入指令解析，
其余字节全部丢弃。这样可以避免串口线上的噪声不断刷新超时计时器，
让断连保护形同虚设。

## 代码结构

```
RC_Car/Core/Src/main.c
├── PD 区      宏定义：PWM_MAX / SPEED / CAR_TIMEOUT_MS / 各诊断开关
├── PV 区      全局状态：car_cmd / last_cmd_tick / g_speed / g_dir / rx_any_cnt
├── USER CODE 2
│   ├── HAL_TIM_PWM_Start ×2        启动双路 PWM
│   ├── Car_Stop()                  上电先停车
│   ├── HAL_UART_Init()             覆盖波特率
│   ├── PA10 重配为上拉输入         ⚠️ 关键修复，见排障日志
│   └── HAL_UART_Receive_IT()       开中断接收
├── 主循环
│   ├── PC13 诊断仪表               心跳 + 收到数据指示
│   ├── 指令解析                    switch-case 状态机
│   ├── 断连保护                    超时归零
│   └── 电机执行                    Car_Run / TurnLeft / TurnRight / Stop
└── 回调
    ├── HAL_UART_RxCpltCallback     收 1 字节 → 存指令 → 重开接收
    └── HAL_UART_ErrorCallback      溢出后复位状态并重开接收
```

关于为什么要有 `HAL_UART_ErrorCallback`：串口线上噪声过强时会产生溢出错误，
HAL 库默认不会自动重新开启接收，一旦溢出就**永久收不到数据**，表现为"突然完全没反应"。
这个回调手动清标志并重新武装，让串口能自己恢复。

## 编译与烧录

1. 用 **STM32CubeMX** 打开 `RC_Car/RC_Car.ioc`，可直接查看外设配置
2. **Keil MDK5** 打开 `RC_Car/MDK-ARM/RC_Car.uvprojx`
3. `F7` 编译 → 看到 `compiling main.c` → `LOAD` → `Verify OK` → 按板载 RESET

> 如果烧录后行为没有变化，先对比 `main.c` 与 `RC_Car.axf` 的时间戳，
> 确认真的重新编译了。这个坑踩过一次。

## 调试工具

`tools/uart_diag.py` 是一个基于 pyserial 的串口诊断脚本，
用于绕开蓝牙、用 USB-TTL（CH340）直连 HC-05 做验证：

```bash
python uart_diag.py list                  # 列出串口
python uart_diag.py loop  COM3            # 环回测试（短接 CH340 的 TX/RX）
python uart_diag.py at    COM3 38400      # AT 指令测试（EN 接 3V3 后上电）
python uart_diag.py sniff COM3 9600 6     # 被动监听 6 秒
```

依赖：`pip install pyserial`

## 遇到过的问题

详细排查过程见 **[docs/DEBUG_LOG.md](docs/DEBUG_LOG.md)**，三个最有价值的：

| 问题 | 根因 | 修复 |
|---|---|---|
| 只有左电机转 | L298N 的 IN 脚自带上拉，悬空即 (1,1) 刹车 | 接入 GPIO 驱动 |
| 手机发指令，单片机一个字节都收不到 | USART RX 引脚被 CubeMX 生成为**浮空输入**，弱驱动信号无法识别 | PA10 改为内部上拉输入 |
| 电机一转蓝牙就断线 | 电池 6V 经 L298N 板载 78M05 稳压压差不足，电机启动电流拉垮 5V 母线 | 控制电源与动力电源分离，只共地 |
